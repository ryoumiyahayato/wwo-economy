# 第二轮综合经济候选

基于第一轮 `70d6b5e40d279d944bd5e5da0445156a71df2fa6`，同一手动工作流新增
`round2-full`；55 分钟总上限，每个阶段另设有时限的子进程。每次综合任务只恢复一次
已校验的源码及三个资源卷；原 Release 保持不变，不下载任何玩家存档。
原始压缩包先校验，然后将当前候选的受控覆盖层应用到隔离工程；逐文件记录前后 SHA256。
删掉隔离工程的 `.godot` 后实际导入，使用官方 Godot 4.6.3 和官方 SHA512。

阶段独立记录失败；导入失败后仍尝试有条件运行不依赖故障部分的经济检查。
不在用户 Windows 或本地启动引擎；Godot 操作只由 GitHub 托管 Linux 执行。

- `benchmark50` 使用原 `run_global_market.gd` 的算法与50区域/16商品/120边，
  基线、供应、需求、运输及组合冲击各运行365日；旧 `benchmark` 接口保持可用。
- `coupled-fresh` 从同一个新建、预热24日的 Formal 区域世界快照分叉，再各运行30日。
  不读取旧试玩/玩家存档；因此与旧现金125→103、面包96、粮食订单各12、
  指数判断9/改价0的历史数据比较须标注初始条件不同，不能冒称严格历史重放。
- `industry` 在原区域工厂、设备、劳动力、工资和 Formal 生产器中配置
  有限煤2+铁矿1→钢1。充足/缺煤/缺矿三组只有初始材料不同；
  核对原 StockLots 消耗、实际产出、现金和恢复一致性。不用宏观缓冲充当原料。
- `trade` 从实际空间目录寻找伦敦港—勒阿弗尔航线，配置明确开发卖方、买方、
  承运人、有限货源及2单位/日容量、2日航程。双方约定原 Formal 本币结算；
  这是显式开发合约，不声称历史英国企业使用法币，也不伪造汇兑。
  真实订单预留→运输→收货→货款和运费结算必须全部发生，重复命令不得重复扣款。
- `gen23_economy.py` 新增独立 `private.wwo.gen23-economy.v2`，要求精确候选SHA、
  已校验的覆盖层文件清单和真实引擎版本。旧v1仍检查旧固定提交，没有关闭版本保护。
  复用原人物宿主和网页 `NativeEconomyScene`，原身份、已知报价、原命令及状态差异仍来自原世界。
- `ui` 实例化原全球地图场景及原商号，商号接入新建宿主，检查桌面和移动尺寸布局。
  不将无GPU布局检查描述为移动设备帧率或人工游戏验收。

Artifact 配额已满，综合模式完全跳过 Artifact 上传，不重试。主要证据写 Actions Summary、
有限日志及 `WWO round2` check annotations。annotation 内为 zlib+base64 压缩的小型JSON，
供读取真实结果，不包含原玩家存档、凭据、地图或完整工程。审阅后的少量数值和因果记录
可以提交到本仓库。各阶段PASS仅表示其明确断言成立；不自动证明完整综合闭环或历史真实性。
