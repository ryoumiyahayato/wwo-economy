## 1. 当前生产率的真实公式与执行路径

原路径仍为 `EconomySliceConfig.valid/normalize → EconomyR1Slice.bind/initialize → 原 GameClock/SimulationStep → settle_day → _plan_firms → 已发生工作/工资责任 → _allocate_production → _produce → StockLots/CostAllocation`。

每活动每批工时 `h`、合格产出 `y[g]`、材料 `m[g]`、能力消耗 `c` 都是显式整数配置。按活动次序执行：

```
实际批次数 b = min(
  原计划当日批次,
  floor(剩余已工作人时 / h),
  floor(适配、可用、共享设备池能力 / c),
  对每种所需材料 floor(本站未被原责任预留的货批数量 / m[g]),
  本合同当日周期批次限额和剩余累计批次额度,
  原整数数量和库存累计上限)
实际合格产出[g] = b × y[g]
实际材料消耗[g] = b × m[g]
分配到生产的人时 = b × h
```

不是“劳动×效率”的连续万能公式。需求先决定计划：本站库存目标、已接订单、收到的请求、历史订单、已接受入库和规划窗口影响想生产多少；没有需求不强制开满设备。劳动、设备和材料依次共享，不能各条活动重复使用同一投入。设备在上一生产区间有效才计入能力，午夜新安装设备属于下一生产区间。

执行时选择本站真实 portion，消费输入，再创建正式 output source/portion；原资金预留、权限、订单锁价、发运、交付、付款和消费均保留。资金不足不再次扣一份生产工资，而是影响采购、已有工资的支付及可选经营行为；到期工资仅支付可用现金，余款留作真实责任。

技能目前是岗位入职门槛，没有“技能2便产量翻倍”的乘数，也没有活动级职业劳动隔离。不同活动的 h/y 可以不同。已有 ACTIVE 安装资产能增加适配能力，暂停/维护/拆装资产不贡献相应能力；本轮设备对照使用明确的初始站点能力，没有声称完成了真实机器购买或新技术研发。

此前 `multisite()` 的粮食开发活动为 `hours=1, outputs.grain=2, materials=0, capacity_units=1`。所以有1已工作小时和1能力单位就可执行一批、得到2个当时的开发粮食单位。它没有土地、种子、水、农事周期、天气或矿藏权威；**不是农业经验生产率，更不是全产业生产公式**。本轮农业/天然纤维再生产及采矿的相应约束明确 UNAVAILABLE，只允许销售有限开仓货批。

## 2. 已配置化的统一合同及支持边界

复用原活动、站点、岗位、设备池和唯一执行器。新增可选 `process` 严格校验：工艺ID、批次单位、出处/估计性质、人时/能力单位、正常潜在产出、不合格品、首次可开工日、离散周期、每周期批次上限、累计批次上限及不可用约束。旧配置不带 process 保持旧行为，标明 `LEGACY_UNSPECIFIED`，7日原区域配置及正式恢复通过。

已有参数包括商品ID/计量单位、材料数量、firm/site/合法place、每批人时、岗位技能和工资、设备适配能力、生产计划、库存目标、采购关系、运输时长/容量/运费及成本责任。新增字段见[合同](../ECONOMY_READ_CONTRACT_V1.md)，实际进入原计划和执行的同一条路径。无独立库存、资金池、时钟或第二套生产系统。

- 粮食、面粉、纤维、煤、矿石、钢材以 kg；布以 m；口粮、成衣、工具以 piece。`bread` 是原ID下的开发干制口粮替身，**没有冒称已实现面包烘焙的水、燃料、烤炉和热过程**。
- 磨粉基准：粮食3kg/2人时 → 合格面粉2kg，合同正常潜在产出3kg、不合格/损耗1kg；后者不创建可售废料。钢材为煤2kg+矿石3kg/2人时 → 钢2kg，仍是明确开发配比。
- 土地、生物周期、矿藏、活动岗位隔离、特定机器、未接入燃料、无实物服务产出及多日在制品，若声明为必要而未实现，则 UNAVAILABLE，批次数必须为0。
- 周期仅是允许批处理的每日边界，没有隐含在制品或跨日劳动储存。累计批次上限不是矿藏吨数或土地面积。真实服务继续由原 ServiceMarket；车船/场站/燃料应适配原 SharedTransport/CapitalTransport，本轮不将各行业一口气实现。

原 Formal 财产权、账本、货批、地点、权限和结算为正式机制；上述配比、初始现金/库存、工资、报价、需求、目标和能力都是开发估计，尚非1900年统计。
